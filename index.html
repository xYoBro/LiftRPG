Step 1 Start the bridge on your machine
This door uses the coding agent you already have installed, on your own subscription, instead of a metered API key. A small program on your machine — the bridge — hands LiftRPG's requests to that agent and hands the answers back. It never sees your login, and nothing is sent anywhere except by the agent itself.
Get the bridge
Download The Bridge One file, liftrpg-bridge.mjs. You need Node installed and a logged-in Claude Code; if either is missing, the bridge’s first line names the exact fix.
This command is written for the LiftRPG folder’s own copy. If you downloaded the single file above, run it from wherever you saved it — node liftrpg-bridge.mjs, with the same flags.
You are ready when its first line reads found Claude Code, logged in, ready on :8090
If it prints something else
The bridge checks itself before it starts serving, and its first line is either the ready line above or the exact fix. These are the three it can print instead:
  • Claude Code CLI not found (claude). Fix: npm install -g @anthropic-ai/claude-code
  • Claude Code is installed but not logged in. Fix: claude auth login
  • Port 8090 is already in use. Fix: stop the other process, or run with --port <n>.
If you move it to another port with --port, change the Base URL below to match.
Step 1 Where should LiftRPG send the work?
Pick a provider from the list, or point the Base URL at any service that speaks the OpenAI API — Moonshot (Kimi), OpenRouter, Together, DeepSeek, or a model running on your own machine. Choosing a provider fills in a sensible Base URL; overwrite it whenever you are going somewhere else.
Running a model locally? Ollama and LM Studio both serve an OpenAI-compatible endpoint on your machine, and most local servers need no key at all.
Step 2 Your key
Held in this tab for this session only. It goes straight from your browser to the provider you chose — LiftRPG has no server in the middle and never stores it. It is also what lets the next step ask your provider which models it offers.
Step 3 Which model writes the booklet?
Refresh Models asks your provider what it currently offers. If your model is not on the list — or the provider does not publish one — choose Custom model and type the id yourself.
LiftRPG can load the current model list from supported providers so you do not have to keep updating this field by hand.
Step 4 How should it build?
The default writes the book one part at a time, checking each part before it pays for the next — the most consistent result on most models. The timeout is how long LiftRPG waits before giving up on a single request; slow stages are allowed to take longer than this.
Advanced

This step sets the title, cover, rules, and theme before the content pages begin.

What this door does not do: the API build modes run a game design step before anything else — the model writes the game’s rules (how you win, what you do, what the currency is, how the password is earned) and everything after is written to serve them, with the play spine checked against those rules both ways. This guided path skips that step, so the game’s shape is decided here alongside everything else and nothing checks the two against each other. It also means the weeks, found documents and endings on this path are written without those rules in front of them: on an API build mode every one of those stages is handed the game’s currency, its core verbs and its win condition as a given, plus the week’s own row of the tension budget — this door has none of that to hand them. Use an API build mode if you want the rules-first pass.

And one more: the API build modes run an economy pacing step after the identity step, where the model says how often the player touches each part of the economy — every week, once, inside a window that closes, or arriving later on purpose. Each week is then checked against that promise as it is written, so a gauge the rules feed every week and the pages print in one week of six is refused rather than delivered. This door has no such step and no such check, so a surface the rules assume from session one can simply be missing from a week and nothing will notice.
